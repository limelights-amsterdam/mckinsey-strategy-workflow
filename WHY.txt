MCKINSEY-STRATEGY-WORKFLOW — WHY, HOW, AND WHAT IT'S WORTH
==========================================================


THE EXPERIMENT THIS CAME FROM
-----------------------------
This repo is the answer to one question: do you actually NEED the experimental
"agent teams" feature to run the mckinsey-strategy-team skill, or does a plain
deterministic workflow do the job?

We analyzed the team skill and found that ~90% of it is "spawn agents in
parallel, wait, read their files". The teammates communicate via FILES, not
messages; they go idle after writing one file; deep mode even re-spawns them
instead of reusing them. The team infrastructure was plumbing, not capability.
So we rebuilt it as a workflow script. This repo is the result.


1. WHAT WAS CHOSEN (and why)
----------------------------
A DETERMINISTIC WORKFLOW SCRIPT (workflow.js) with the same wave structure as
the team version, instead of a live agent team.

a) Workflow instead of teams.
   What you gain:
   - The TALLY RULE AS CODE. The house rule — an assumption >=2 verifiers
     independently flag as fatal does not survive — was the team lead counting
     flags by judgment. Here it is four lines of deterministic JavaScript, and
     the memo agent receives the result as BINDING input. The most important
     guardrail in the method went from "please remember to do this" to "cannot
     be skipped".
   - No experimental flag, no Claude Code version gate, no TeamCreate/TaskCreate/
     shutdown boilerplate, no "what if teams is off" fallback path.
   - RESUMABILITY. If a run dies in wave B, resume it: finished agents return
     cached, only the rest reruns. The team version re-runs waves by hand.
   - Reproducibility. The same brief gives the same orchestration every time —
     the lead cannot forget a wave, skip the filter step, or shrink the panel.

   What you lose (be honest about it):
   - Steering a NAMED teammate mid-run (SendMessage). In practice the team
     version's checkpoints all sat BETWEEN waves at the lead level, so the
     real steering moments — intake and reviewing the result — survive intact.
   - The deep-mode teammate-vs-teammate debate. Approximated here by the
     tournament (three judge lenses) and the war-game loop.

b) Checkpoints move to the edges.
   A workflow runs unattended once launched — it cannot pause to ask you a
   question. So the intake got HEAVIER on purpose: everything the lead would
   have steered mid-run must be in brief.md before launch. The "OK to spawn?"
   checkpoint becomes "OK to launch?", and iteration happens by editing the
   brief and RESUMING (cached waves are free).

c) The 21 McKinsey-style frameworks as a REFERENCE LIBRARY inside the skill,
   not 21 separate skills. Workflow agents inherit nothing, so they READ the
   framework files. Same choice as the team version, same reason: it always
   works.

d) The Six Workflow Patterns, now literally as code.
   A STANDARD run: classify-and-act (intake), fan-out-and-synthesize (wave A),
   generate-and-filter (wave B: bull vs lean mandates, then one filter agent),
   adversarial verification (the panel + the coded tally).
   DEEP MODE adds: tournament (judges with economics / feasibility / strategic-
   fit lenses pairwise-judge the shortlist, king-of-the-hill; an overturned
   draft is re-synthesized) and loop-until-done (war-game rounds until two
   consecutive rounds surface no new fatal risk, capped at 5).
   In the team version these patterns were prose instructions; here they are
   control flow. A pattern that is code cannot be forgotten.


2. HOW IT WORKS
---------------
You start it with: "use the strategy workflow to prepare a decision on X."

STEP 1 — Intake (the checkpoint). The lead pulls the real decision question,
   audience, output language, constraints, known facts, and confirms standard
   vs deep mode. Then it shows the plan: "I'll launch with this brief — OK?"

STEP 2 — Brief. All context goes into /tmp/strat-wf-<slug>/brief.md. Workflow
   agents inherit nothing; the brief is their entire world.

STEP 3 — Launch. One Workflow call with {ws, refs, deep}. Then, unattended:

   WAVE A    diagnose + market in parallel. The factual floor. Options are
             deliberately NOT generated here — they must stand on findings.
   WAVE B    option-bull (maximize upside) and option-lean (cheapest
             reversible path) generate 2-3 options each, with "what must be
             true". Deep mode adds option-contrarian (consensus forbidden).
             Structured output, schema-enforced.
   FILTER    one agent dedupes, drops dominated options, scores survivors,
             picks a recommendation, numbers the assumptions A1..An.
   TOURNAMENT (deep, 3+ survivors) judges pairwise-compare champion vs each
             challenger; 2-of-3 votes overturns the draft.
   PANEL     verify-assumptions, verify-wargame, verify-execution attack the
             draft in parallel and return fatal assumption IDs via schema.
   TALLY     code counts the flags. >=2 independent flags = fatal = must be
             fixed, hedged, or the recommendation changes. Binding.
   RISK LOOP (deep) extra war-game rounds until two consecutive rounds find
             no new fatal risk.
   MEMO      decision question, Pyramid recommendation, option trade-off
             table, risks + mitigations (tally-fatal marked), first 90 days,
             a 60-second spoken story, 3 hostile-Q&A answers.

STEP 4 — Deliver. The lead reports the recommendation + which assumptions
   died, copies the memo to a durable path, and offers a resume-based
   iteration if you want changes.


3. WHAT IT'S WORTH
------------------
- The same thing the team version is worth — an analysis that SURVIVES the
  meeting, structure on a fuzzy question, parallel depth, a shareable memo —
  MINUS the experimental-feature tax, PLUS a guardrail that physically cannot
  be skipped and runs that can be resumed and reproduced.

- A clean A/B answer to "do I need agent teams for this?": no, not for this
  shape of work. Keep the team version when you want to watch named teammates
  live and steer them mid-run; use this one when you want the engagement to
  just run, identically, every time.

COST / WHEN NOT. A standard run is ~8 agents, deep mode ~15+ — noticeably more
tokens than an ordinary chat. Use it for real decisions, not a quick question.
For a single framework, read that framework file directly.
